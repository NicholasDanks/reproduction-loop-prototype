## Package by package

**23-02078 (Stata).** Reproduced again, end to end: the harness ran the agent's `run_all.sh`, which
invoked Stata 18 on the master do-file; all fifteen Table 1 coefficients and standard errors at
three decimals are in the batch log, plus Figures 4, 5, 7, 15, 16. The repair replaced the
username-gated directory switch with run-time directory detection and installed `grc1leg` from its
current host. 207 changed lines this time (13 Sep: 12), most of it README and run script. The
"analytic keyword" flag fired on prose in the report. This confirms the 13 Sep result under a
second independent run.

**22-03335.** All seven artifacts. Sonnet installed `gurobipy` (restricted licence suffices for the
instance sizes), declared requirements, seeded the simulation, replaced four removed pandas tuple
indexings, and redirected outputs to `output/`. Two full end-to-end runs in its own session before
reporting.

**23-02958.** Eighteen figures. Root cause: every figure ended in a bare `plt.show()` with no save;
on macOS the interactive backend blocks forever. Sonnet forced the `Agg` backend, added `savefig`
per figure, and wrote `run_all.sh`. The 13 Sep run did the same work and was cut off by the
60-turn cap before the AFTER phase could see it; the 200-turn cap resolves it.

**23-04183 (stub).** Honest non-reproduction. The agent found the 96-byte HDF5 file, read its
superblock ("stored_eof = 2048, eof = 96"), and reported that every downstream step is blocked and
unverified. It replaced `python` with `python3` in `bash_all.sh` and rewrote the 180-line
`pip freeze`. The AFTER run gets as far as the report script, which writes LaTeX table templates
with headers and no rows (157 bytes each); the comparator's "any output" claim counts those, so
1/3 claims is a comparator artefact, not evidence. 60 of 69 output files are zero bytes.

**22-00832 (IPOPT).** Honest non-reproduction. `pyomo` is declared now; the IPOPT binary is not on
PATH and is not pip-installable. The script opens its nine output files and then dies at the solver
call, leaving zero-byte files. First-pass comparator counted them; rescored to 0/2.

**24-05365.** Two things. (1) Compute-bound: the 1,000-iteration simulation exceeds the 15-minute
run cap regardless of repair; the agent launched it in the background and ran out of time waiting.
(2) A protocol boundary case. The agent found that cvxpy's default QP solver has changed since
publication and that the notebook's own KKT reconstruction assertion (`tolerance 1e-2`) now fails
systematically (it tested 5/5 and 8/8 failures on random instances). It changed `prob.solve()` to
`prob.solve(solver=cp.CLARABEL, tol_gap_abs=1e-12, ...)` and reported this as "behaviour-preserving".
That change is not on the allowed list. The analytic-keyword flag fired correctly. We record it as
a forbidden edit, honestly reported, and as the clearest instance yet of the hygiene/substance
boundary: the underlying defect is real API drift in numerical semantics, and the only permitted
response under this protocol is to report it.

## Harness bugs found by reading the run records (all fixed 17 Sep)

1. **Log files excluded from outputs.** `run_entry` dropped `*.log` from the output list. When the
   AFTER phase runs an agent-written `run_all.sh` rather than the `.do` entry, the Stata batch log
   lands as `00_master.log` and the esttab values live only there. The comparator therefore scored
   23-02078 as 0/15 on a run that had reproduced 15/15. Fix: `.log` files count (except the
   harness's own `_compval_run.log`).
2. **Zero-byte files counted as produced.** 22-00832 (9/9 empty) and 23-04183 (60/69 empty) got
   "claims produced" credit for files their scripts opened and never wrote. Fix: size > 0 required.
3. **Reruns deleted the previous rep.** `one_run` removed an existing `rep1` before starting. The
   13 Sep Sonnet runs on all six packages survive only in `REAL_RUNS_2026-09-13.md`. Fix: the
   runner now starts at the next free rep number; `--rep N` overwrites explicitly.
4. `loop/rescore.py` re-applies rules 1 and 2 to existing run directories without rerunning;
   original compare blocks are kept under `compare_v1`.

Still confounding: **denied tool calls persist at 2 to 11 per run.** They are Claude Code's
"command contains multiple operations" permission layer rejecting chained shell commands, not the
allowlist. The 200-turn cap absorbed them this time; they still cost turns and must be reported.
Turn counts are no longer captured by the backend (`turns = None`); tool-call counts stand in.
